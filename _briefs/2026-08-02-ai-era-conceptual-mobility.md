# 选题契约

## 唯一命题

**AI 时代真正稀缺的概念能力，不是记住一个永恒而精确的定义，而是能够根据行动后果选择正确的颗粒度，让概念在体感边界、关系模型、工作定义、可执行 eval 与现实反馈之间完成可逆转换。**

全文只推进这一条判断。Agent、经验与知识、作者的 AI 对话方式、未来人才形态和提问阶梯都必须服务于这条主线，不要扩写成五篇并列文章。

## 为什么值得由我写

1. 作者本轮思考始于一个真实交流摩擦：他知道 Agent 的体感边界，却不能立即给出一句自己满意的定义；他会区分经验与知识，对方却追问二者的包含与关系。这不是假设案例，是作者在交流中实际遇到的表达问题。
2. 作者长期围绕一个公开候选主命题做工程：“让上下文在工具切换之间不丢失。”DayPage、brain、cct、files-as-context、`hot.md` 和 provider 抽象等项目与设计反复处理状态、边界、上下文和编译。这使“概念如何被另一个人或 Agent 正确加载”成为长期实践问题，而非临时哲学兴趣。
3. 作者的独立增量是把自己的隐性思考方式暴露出来：概念在他脑中通常不是孤立词条，而是由相邻概念、正反例、上下游、准入门槛、状态变化和行动后果共同定义。
4. 文章必须保留反证：关系感和边界体感可能只是未经检验的直觉；漂亮的多维框架也可能逃避清晰承诺。只有概念能够被翻译、操作化并接受现实推翻，这套能力才成立。

## 目标读者与阅读场景

- 读者：
  - 经常使用 AI、Agent、知识库和自动化系统的开发者、产品经理、研究者与创作者；
  - 面对快速出现的新概念，既不满足于营销术语，又不想陷入无休止定义争论的人；
  - 正在思考 AI 普及以后，人的判断、学习、提问和协作能力会怎样变化的人。
- 场景：
  - 会使用 Agent 产品，却无法准确解释 Agent 与 chatbot、workflow、automation 的边界；
  - 与别人讨论知识、经验、智能、创造力、判断等词时，发现双方说的是同一个词，却在不同坐标轴上回答；
  - AI 能迅速生成定义、框架和文章以后，开始怀疑“概念理解”本身还有什么价值。
- 期望效果：
  - 读者不再把“背得出定义”和“真正理解”混为一谈；
  - 学会判断何时应保留模糊、何时需要工作定义、何时必须把定义写成可测试的 eval；
  - 得到一组能够检验他人和自己理解深度的问题，但不把它变成身份排名。

### 作者观察

以下内容是本轮对话中逐步收束、并因作者明确要求下发而获准作为文章判断骨架。平台侧可以推敲措辞和加入反方，但不得另造作者经历。

1. 作者更接近“关系边界型”而非“词典定义型”的概念理解：
   - 理解 Agent 时，先感觉它与 workflow、chatbot、automation 的差别；
   - 理解经验与知识时，先看到经验如何经反思、抽象、验证变成候选知识；
   - 一个概念往往通过相邻概念、正反例、状态变化、上下游和行动后果获得意义。

2. 概念至少有五种形态：

```text
体感          = 尚未显式化的高维判别器
关系          = 概念与相邻对象、因果和上下游组成的地图
工作定义      = 为当前协作与决策做的有边界压缩
eval          = 可以被系统执行、观测和否证的定义
现实反馈      = 迫使概念更新的外部结果
```

   不要把等号写成学术事实；它是本文用于组织思考的工作模型。

3. 中心转化链：

```text
体感
  ↓ 拆出正反例与区分轴
边界判别
  ↓ 放回相邻概念与因果关系
关系模型
  ↓ 为当前任务压缩
工作定义
  ↓ 写成可观测标准
eval / 权限 / 停止条件
  ↓
行动与现实反馈
  └──────────────→ 修正概念
```

4. Agent 不宜只作为二元名词争论，可以先拆成多维画像：
   - 路径自主性：下一步由谁决定；
   - 环境作用力：只能生成文本，还是能调用工具改变外部状态；
   - 反馈适应性：中间结果是否改变后续路径；
   - 状态持续性：是否保留跨步骤、跨会话状态；
   - 任务跨度：一次调用、数小时任务或长期目标；
   - 权限与风险：能读什么、修改什么、提交什么；
   - 人类介入：何时询问、暂停、确认与移交。
   同一系统可能在不同维度表现不同，“Agent 程度”有时比“是不是 Agent”提供更多信息。

5. 经验与知识不是简单互斥集合：
   - 经验更接近“我实际经历、做过、观察过什么”；
   - 知识更接近“从材料中形成了什么相对稳定、能够预测或指导下一次行动的判断”；
   - 不是所有经验都会自动成为知识，也不是所有知识都必须来自个人亲历；
   - 区分二者是为了看清它们在认识过程中的功能，不是切断二者关系。

6. 概念需要多精确，取决于行动后果：
   - 探索阶段：允许模糊，先积累案例、反例和体感；
   - 建模阶段：拆关系、区分轴、因果和边界；
   - 协作阶段：冻结一个有版本、有适用范围的工作定义；
   - 自动执行、高风险、科学测量或标准制定阶段：必须精确到权限、阈值、验收和停止条件。
   - 不要把“定义不重要”写成主张。本文主张的是“精度与后果匹配”。

7. AI 时代的高层级不是抽象得更高，而是拥有“垂直机动性”：

```text
具体事件
↕
重复模式
↕
作用机制
↕
系统结构
↕
长期不变量与价值选择
```

   真正理解深的人既能上升，也能下降；能从具体 bug 上升到状态与权限问题，也能从“Agent 自主性”下降到“失败三次以后系统具体做什么”。

8. 未来稀缺的人可以写成五种能力的组合，而不是五种职业标签：
   - 现实持有者：拥有一手现场、数据、关系、失败和后果；
   - 问题定义者：决定目标、约束、取舍、成功与推翻条件；
   - 颗粒度控制者：能在案例、机制、系统和价值之间切换；
   - 评价器设计者：把“好”变成 rubric、grader、反例和失败回流；
   - 承诺与责任承担者：愿意选择、下注、关掉部分可能，并对结果负责。
   不得宣称这些能力永远不能被 AI 获得；文章讨论的是在当前趋势下价值向哪里迁移。

9. AI 对作者的作用：
   - 外部工作记忆：保留前文和长期上下文；
   - 概念编译器：把体感扩成名称、关系与结构；
   - 镜子：作者通过“这像不像我的真实判断”筛选候选解释。
   - 风险：AI 形成自洽候选模型的速度可能超过本人裁决、公共语言协商和现实验证的速度。

10. 本文最终不是歌颂抽象，而是要求五种可逆转换：

```text
体感 ↔ 语言
案例 ↔ 模型
模型 ↔ eval
判断 ↔ 行动
私人理解 ↔ 公共语境
```

### 待验证推论

以下内容可以作为文章推论，但必须用“我的判断、当前趋势下、可能、至少在这类任务中”等限定语，并配置反方：

1. 当 AI 能廉价生成定义、框架和推理链后，存量概念的记忆价值下降，选择问题、控制颗粒度、设计 eval 和吸收现实反馈的价值上升。
2. AI 普及后，“定义”不会消失，反而会更多地以接口、schema、rubric、权限和终止条件的形态进入系统。
3. 未来真正稀缺的学习能力，可能不是掌握更多已有技能，而是面对陌生问题时，以较少经验迅速形成可修订模型。
4. 高水平理解可以通过正反例、反事实、决策后果、失败边界和跨颗粒度翻译被部分观察，但不能据此给人的整体价值排位。
5. AI 能否承担更高层问题定义、评价与责任会持续变化。本文不能把当前人机分工写成永恒边界。

### Agent 的工作定义与维度

### 定义、体感与隐性知识

- Ludwig Wittgenstein《哲学研究》中的 family resemblance：概念是否一定共享单一必要本质。优先找可靠版本、学术条目或原文段落，不用流行二手金句。
- Michael Polanyi《The Tacit Dimension》：人可能知道得比能够明确说出的更多；核验原意，不能把“体感”自动神圣化。
- Gilbert Ryle《The Concept of Mind》：knowing how 与 knowing that；用于区分会辨认/会行动与会陈述命题。
- Eleanor Rosch 关于 prototype 与 semantic categories 的原始研究：人如何依靠原型与典型性组织概念。
- Percy Bridgman 的 operationalism 及其后续批评：操作性定义何时增加可测性，何时把对象错误缩减为测量程序。
- 最强反方：隐性知识可能只是无法解释的偏见；“家族相似”不能成为拒绝清晰、可证伪命题的借口。

### AI 时代的高层工作

- OpenAI, “Harness engineering”：核验人的工作如何向环境设计、意图表达、上下文可读性、反馈循环和 taste invariants 迁移；同时保留其仍属特定团队实验的边界。
- François Chollet, “On the Measure of Intelligence”：核验 skill-acquisition efficiency、priors、experience、scope 和 generalization difficulty；不要把一篇论文提升为智能的唯一公认定义。
- 作者自己的公开文章与项目：
  - “从信息到创作”专栏；
  - “Context 不是 Prompt”；
  - DayPage / cct / brain 的公开介绍；
  - 站内查重后选择 2—3 个内链，避免自我引用过载。
- 最强反方：
  - AI 也能生成目标、rubric、反例与跨层解释，所谓“高层能力”可能继续被商品化；
  - 强调判断、品味和责任可能沦为新的模糊身份优越感；
  - 现实持有者也会受样本偏差、利益和有限视野影响，不能自动高于形式知识。

## 文章方向

### 建议结构

建议 5,500—8,000 个中文字。采用专栏式思考长文：具体瞬间 → 中心模型 → 两个案例 → 精度阶梯 → 未来人才形态 → 提问阶梯 → AI 反方 → 个人检验标准。

#### 1. 我知道什么是 Agent，却说不出它的定义

- 用作者原话进入，不用“在 AI 时代”。
- 写清当时的尴尬：能辨认正反例，却无法给出一句没有漏洞的定义。
- 第一屏 Answer-First：
  - 会背定义不等于理解，只有体感也不足以协作；
  - 真正稀缺的是把体感、关系、定义、eval 和现实连接起来；
  - 给出一个最小 Agent 工作定义作为示范，但立刻说明它服务的是工程讨论，不是终极本体论。

#### 2. 我拥有的不是定义，而是一个尚未显式化的判别器

- 区分：
  - “看见系统后能判断像不像”的边界判别；
  - “给出必要条件与充分条件”的孤立定义。
- 用 Agent 正例、反例和争议例说明两者不同：
  - 固定路径 workflow；
  - 能在结果后调整路径、使用工具、停止或移交的系统；
  - 能自主规划但不能作用外部世界的灰区。
- 引入 Polanyi / Ryle / Rosch 或 Wittgenstein 中最能服务论点的 1—2 个，不要做哲学家名单。

#### 3. 概念不是一个词条，而是五种可以互相编译的形态

- 放全文中心图：

```text
体感 → 边界 → 关系 → 工作定义 → eval
  ↑                              ↓
  └────────── 现实反馈 ← 行动 ───┘
```

- 逐个解释：
  - 体感为何高维但不可直接协作；
  - 关系为何比孤立定义保留更多结构；
  - 工作定义为何是有目的、有版本的压缩；
  - eval 为何是可以执行的定义；
  - 现实为何拥有最终修订权。
- 深度来自转化，不来自新造术语。

#### 4. 经验和知识的争论，暴露了我们在不同坐标轴上说话

- 作者说“区分”，意在区分认识过程中的功能；
- 对方追问“关系”，可能在问集合、包含和来源；
- 用一个真实但不泄露第三方的例子：

```text
做过十次        → 经验材料
比较成败        → 发现模式
写出条件与边界  → 候选知识
换场景再次成立  → 更强知识
新失败出现      → 修正
```

- 说明经验不是知识的反面，而是知识的重要来源和验证场；读书得来的知识也不必先亲历。
- 点出交流错位：一方在问“它们怎样流动”，另一方在问“它们怎样包含”。

#### 5. 定义需要多精确，取决于它将控制什么

- 给出四阶段：
  1. 探索：允许模糊，先收集正反例；
  2. 建模：拆关系、因果、变量与边界；
  3. 协作：冻结带作用域的工作定义；
  4. 自动执行/高风险/测量：落实为 schema、rubric、权限、阈值和停止条件。
- 可提出一个直观关系，不写成严格数学公式：

```text
参与者越多
自动化越深
行动越不可逆
失败代价越高
        ↓
所需定义精度越高
```

- 用 Agent 的产品、架构、安全、评测四个场景说明同一个词需要不同操作化。
- 反直觉点：AI 不会让定义消失，而会让定义从文章里的句子迁入系统边界。

#### 6. 高层级不是抽象得更高，而是拥有垂直机动性

- 用颗粒度梯子：

```text
一次具体行为
↕
重复模式
↕
作用机制
↕
系统结构
↕
长期不变量与价值选择
```

- 只能上升、不能下降的人不是理解深，只是悬空；
- 只能处理当前案例、无法迁移的人有经验，但尚未形成稳定模型；
- 真正强的人能选对当前任务的颗粒度，并在需要时返回现场。
- 连接未来五种能力：现实持有、问题定义、颗粒度控制、评价器设计、责任承担。
- 每种能力写一个现实动作，不要写成形容词画像。

#### 7. 不要问“你懂不懂”，沿着模型往下问

给出可直接使用的提问阶梯，每个问题解释它在测试什么：

1. 给一个确定是和确定不是的例子。——边界判别
2. 你使用哪根轴区分？——维度显式化
3. 它与相邻概念是什么关系？——关系图
4. 去掉一个条件，结论会不会变？——反事实与机制
5. 这个区分改变什么工程或商业决定？——操作性
6. 什么证据会让你修改理解？——可证伪与边界
7. 分别对普通用户、产品、工程和安全负责人解释。——颗粒度切换
8. 如果交给 Agent 执行，你怎样写验收和停止条件？——eval

- 明确提醒：这套问题评估的是当前模型，不是给人的整体价值排序。
- 真正理解深的人可能暂时答不上来，但会澄清语境、拆维度、承认未知并给出验证路径。

#### 8. AI 也会制造一种“我已经想明白”的错觉

- 回到作者自己的 AI 对话方式：
  - 从模糊体感开始；
  - AI 提供命名、分类和候选解释；
  - 作者用“像不像我”筛选；
  - 再上升到更完整的系统。
- 写出收益：AI 是概念编译器和外部工作记忆。
- 写出风险：
  - 自洽不等于真实；
  - AI 生成候选模型的速度可能超过人的裁决；
  - 与 AI 已经共享的上下文，普通对话者并没有；
  - 私人语义系统可能越来越精确，却越来越难被外部加载。
- 这一节必须对作者本人更严格，不把沟通困难都归咎于别人“不够深”。

#### 9. 最终检验不是你能否定义，而是能否完成五次转换

- 用五个问题收尾：
  1. 我能否用正反例把体感说出来？
  2. 我能否指出正在使用哪根区分轴？
  3. 我能否为当前任务给出足够精确的工作定义？
  4. 我能否把它写成可执行、可失败的 eval？
  5. 我是否真的允许现实结果修改这个概念？
- 回扣开头：
  - 作者不必先找到 Agent 的终极定义；
  - 但他应该能说清这次讨论为什么需要这个词、用哪几根轴、它将改变什么决定。
- 不用职业预测或工具清单结尾。

### 可选标题方向

1. **《我知道什么是 Agent，却说不出它的定义》**
   最强个人现场，首选。副标题或 description 兑现“体感、关系、定义和 eval”。
2. **《AI 时代最稀缺的能力，是控制问题的颗粒度》**
   认知承诺更直接，但正文必须解释“控制”而非停在抽象口号。
3. **《高层级不是抽象得更高，而是能回到现实》**
   哲思感最强，注意避免身份优越感。

### 不要写成

- Agent、AGI、知识与经验的术语百科；
- “未来十种稀缺人才”式趋势清单；
- 人类永远负责判断、AI 永远只会执行的静态分工；
- 用哲学家和论文数量装饰作者体感；
- 把对方写成理解浅、作者写成更高层级；
- 把“没有统一定义”当成拒绝精确和证伪的借口；
- 把一套提问阶梯包装成识人术或智商测试。
