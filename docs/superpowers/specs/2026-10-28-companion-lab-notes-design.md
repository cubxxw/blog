# Contextual companion and Lab notes

The author asked to remove the resident Companion from the Dock, summon it from Writing, Notes or a product, and separate technical deep reads from products.

Keep the existing desktop, room and product views. Remove Companion from desktop and mobile Dock navigation; retain the keyboard shortcut and app search as recovery paths. Writing offers an action when a passage is selected and an article action in its tools menu. Notes offers an explicit selected-passage action: only that selection may enter the composer, with a visible source and a reminder that sending shares it. Product details retain a quiet contextual action. Opening the composer never sends a request. Focused reading hides the Dock on desktop as it already does on mobile; exiting focus restores navigation and reading position.

Use **深读 / Lab notes** for the technical writing formerly published below `/projects/<slug>/`, and **作品 / Projects** for the author's products. Keep article source files in their existing sections, move their public URLs to `/lab-notes/<slug>/` (with `/zh/` for Chinese), and preserve all old URLs through aliases and direct redirects. Add a bilingual Lab notes index. Update discovery labels, internal links and source breadcrumbs together. Do not change article prose, product inventory, homepage layout or default BEAR OS entry.

Alternatives considered: changing labels alone leaves shared URLs ambiguous; moving all writing would broaden this task unnecessarily. The chosen route change covers only the existing legacy technical deep reads. Native text selection supplies touch long-press behavior without competing with scrolling or selection handles.

Acceptance covers explicit send, removing a quotation, private-note exclusion, selection clearing, old-link compatibility, bilingual canonical URLs, focus restoration, mobile layout and both themes. No production deployment is part of this branch delivery.
