# Blog Content Quality and CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为双语博客建立统一内容检查、一次构建后验收发布、可证明的上线版本和可恢复的发布后自动化。

**Architecture:** GitHub Actions 编排，Netlify 承载主站，GitHub Pages 手动发布静态备用站。检查、构建、artifact、发布回执和下游适配器通过显式 JSON 接口连接；先影子验证，后切换生产。已有 SEO 业务接口不重写。

**Tech Stack:** Node ESM / node:test、Hugo 0.145.0 extended、Netlify CLI 24.9.0、Playwright、markdownlint、markdown-it、parse5、GitHub Actions、现有 Python CSV 转换器。

**Spec:** [已批准设计](../specs/2026-09-28-blog-cicd-design.md)，2026-09-28 作者回复“设计通过”，并选择 B、允许子代理和 PI CLI。下方复选框保留原始验收要求；实际结果以[迁移证据](../../cicd-migration-evidence.md)为准。

**Execution:** Tasks 1–13 已实现并完成离线回归；作者决定修复全部 70 处历史结构问题，基线为空。Task 14 正在完成最终构建与影子 CI，真实 draft、生产切换及回退仍需环境凭据和平台验收，不计为完成。

## Global Constraints

- 生产域名固定 `https://cubxxw.com`，中文前缀 `/zh/`，英文正文不新增 `/en/` 前缀；保留现有 `/en/sitemap.xml`。
- 生产环境固定 production，不启用 `--buildFuture`；文章时间 `+08:00`，SEO 日报仍使用既有 UTC 日期。
- 保留作者发布确认、不使用 draft、不创建英文占位、BEAR OS 默认视图及现有 SEO 模型隔离。
- 允许直接 main 提交；不引入强制 PR。执行前同步远程并保护无关 `output/`，只暂存当前任务文件。
- 每次生产发布一次站点构建；插件处理、函数打包完成后再验收，部署不重跑构建。独立故障 fixture 可单独构建。
- 普通检查只读；副作用集中于显式修复、部署、业务状态持久化入口。CI 不自动改文章或扩大历史例外。
- 浏览器主要矩阵：Chromium × 375px/1280px × 浅色/深色；交互组件保留 Chromium/Firefox/WebKit。
- `release-receipt` 完整报告 artifact 保留 30 天；必要检查缺失/失败/异常跳过不能变成绿灯。
- 未证明兼容性前不停止当前 Netlify Git builds；不在验证时发邮件或调用付费模型。
- 无凭据仍可完成离线实现与影子 CI。真实平台演练和切换单列验收，不能以代码合并冒充上线。

## Review Focus

1. CRLF、中文路径、转义竖线和 shortcode 包裹正文：保留正确源行号，合法示例不误报，坏表格仍拦截（Task 2、4）。
2. 删除/改名、首次 push、强推和 main 仅前进了状态提交：不漏检、不错误取消有效发布，覆盖被跳过的文章（Task 1、8、11）。
3. artifact 被替换、目录穿越或符号链接：不读取仓库/产物边界以外的文件，也不把 PR 构建晋升生产（Task 4、6、8）。
4. 部署 API 成功但 CDN 仍旧、回执过期或队列乱序：停止下游或重新验证；旧版本不能覆盖新版（Task 8、9、14）。
5. 提供商已创建邮件后进程中断、状态提交冲突：保留 pending 并核对，不自动再次创建（Task 10、11）。

## 公共接口约定

以下名称由 Task 1 在 JSDoc 和运行时验证器中定义；后续任务直接复用，不自行发明别名。

| 类型 | 必需字段 |
| --- | --- |
| `ChangeSet` | `schema:'blog-change-set/1'`、`sourceSha`、`baseSha:null\|string`、`fullScan:boolean`、`files:[{status,oldPath:null\|string,path}]`、`sourceFiles:string[]`、`suites:string[]`、`publish:boolean`、`reason:string` |
| `Diagnostic` | `ruleId`、`file`、`line:number`（1-based）、`severity:'error'\|'warning'`、`message`、`evidence`、`fingerprint`、`waivable:boolean` |
| `QualityReport` | `schema:'blog-quality/1'`、`scope:string[]`、`diagnostics:Diagnostic[]`、`waived:Diagnostic[]`、`ok:boolean` |
| `PageMap` | `schema:'blog-page-map/1'`、`sourceSha`、`clock`、`target:'production'\|'backup'\|'preview'`、`baseUrl`、`complete:boolean`、`pages:[{source:null\|string,url,outputPath,lang,kind,contentHash}]` |
| `ArtifactManifest` | `schema:'blog-artifact/1'`、`sourceSha`、`inputDigest`、`releaseId`、`target`、`clock`、`toolchain`、`files:[{path,sha256,bytes}]`、`fileSetDigest`、`pageMapDigest`、`requiredChecks:string[]`、`checks:[{name,status,reportDigest}]` |
| `ReleaseReceipt` | `schema:'blog-release/1'`、`sourceSha`、`inputDigest`、`artifactDigest`、`runId`、`runAttempt`、`siteId`、`deployId`、`deployUrl`、`verifiedAt:null\|string`、`pageMapDigest`、`checks`、`status:'verified'\|'verification-failed'\|'superseded'\|'rollback-verified'` |

`sourceSha` 为完整 40 位 Git SHA；摘要为 SHA-256；clock 为冻结 UTC ISO 时间。target、schema 和 status 拒绝未知值。checks.status 使用 `success|failure|cancelled|skipped`；requiredChecks 从受信任的 changeSet/执行政策计算，不信任 artifact 自行删减。`suites` 只允许 `source,output,browser,interactive,functions,seo,workflow`。命令正常通过退出 0、已知质量违规退出 1、运行/输入不可用退出 2；两种非零都阻断必要门禁。CLI 的 `--all` 和 `--change-set` 二选一，禁止隐式空范围；`--report-only` 可输出历史报告但不能供生产门禁使用。
