# 2026-11-15 存储维护：冷归档与外置缓存

关联 [GET-564](https://linear.app/getyak/issue/GET-564/move-cold-backups-and-caches-off-the-internal-disk)。本记录仅覆盖作者明确要求的本机存储专项；搜索增长与网站性能未在此验收。没有改文章、主页、搜索召回、发布模式或测试门限。

## 实际容量与范围

基线为新加坡时间 04:13 的 Data 卷可用 21,325,758,464B。05:19 新鲜 statvfs 为 **28,454,457,344B（28.45GB）**，仍未严格超过 40,000,000,000B，缺口 11,545,542,657B；因此清理验收未达标，GET-564 保持进行中。10GiB 只是运行边界。

已把四个经过独立审查的冷归档或静态备份依赖迁到外置加密 APFS 区，保留原路径的兼容链接：

| 范围 | 普通文件 | 内置原副本的文件分配块字节 |
| --- | ---: | ---: |
| 已退役任务的内容寻址恢复副本 | 32,870 | 5,831,528,448 |
| 第一份历史恢复备份 | 4,121 | 1,173,352,448 |
| 第二份历史恢复备份 | 4,122 | 1,172,140,032 |
| 冷备份中的静态依赖 | 12,797 | 126,701,568 |
| 合计 | 53,910 | 8,303,722,496 |

这是文件分配量，不是独占物理释放量。APFS 共享块、延迟分配及并行写入会影响主机余量，不能把目录统计或初末容量差全算成本任务收益。备份中的共用 Git 历史依赖继续保留；不把这些副本说成独立 Git 历史或异盘备份。

## 持续写入的位置

Go 构建、Go 模块和 pip 的用户默认缓存已设到外置盘上的私有加密区，并读回实际配置。新卷启用所有权检查，根目录 0700；随机密钥仅保存在本机 Keychain，通过标准输入传给系统挂载工具，不进入命令参数或日志。已配置登录和卷挂载时恢复，并核对当前启动状态；没有做重启或断电恢复验收。

npm、pnpm、uv、Colima 和新登记的大型测试产物原本已在外置盘，本轮读回确认。没有移动活动数据库、登录资料、共享依赖，也没有修改全局 TMPDIR。挂载 helper 遇到缺盘、卷身份不符或 Keychain 拒绝时，会拒绝挂载和内置回退；原生 Go/pip 写缓存前仍须确保私有卷已正确挂载，缓存命令本身不会每次调用 helper。

## 验证、原失败与保留项

所有迁移逐文件核对 SHA-256、uid/gid、模式、时间、flags、ACL 和扩展属性；原逻辑路径完整哈希读回后才清理原副本。非空文件复制回内置私有验收位置，验证内容与权限；合成数据另验证卸载再挂载后的保真。新卷没有改变原外置卷的所有权设置。跨用户 sudo 探针因缺少系统授权未执行，不记为访问隔离实测；没有验证整机灾难恢复。

独立安全审查关闭了目标祖先路径、目录元数据覆盖、并行替代与回滚等问题。8 个安全用例在四份作用域脚本中各执行一次，均通过，涵盖陈旧审查绑定、目录 ACL/xattr 改变、进度写入失败、替代对象保护和中断传播。这些是宿主防护用例，不是浏览器 E2E。

首次原外置镜像比对因元数据差异未认证，原件保留；新复制首轮 quarantine 字段差异在恢复原值后才通过，未忽略隔离属性。第二份备份首次切换又因一个 ZIP 的分配块数变化而退出 1，尚未改动源；重新核对全部字节和元数据、独立审查新凭据后才切换，不能记为整轮首次通过。前置合成检查的 API 和检查时序失败同样保留。

默认 Docker 引擎 28 个容器的身份、镜像、运行状态、启动时间、重启数和挂载前后相同，只证明这组元数据连续。停止的学习引擎引用覆盖仍未知，未启动 VM 或复跑旧磁盘恢复诊断。没有手动终止其他进程或操作设备。

其余运行/回滚版本、活动工作区、历史数据库、原始资料及引用不明的恢复对象继续保护。部分旧依赖存在向外的相对工作区链接，直接搬目录会改变解析结果，不能只凭哈希或年龄迁移；系统拒绝访问的范围保持 unknown。已核查范围不等于整盘穷尽。

## 交付与后续条件

本 PR 仅提交公开维护摘要；私有脚本、完整逐文件回执、原失败和恢复资料保留本机。仓库适用的是现有轻量源检查和 Netlify Git 链，不为文档重复构建网站。本轮网站浏览器、Hugo、完整 performance:check 和新 Lighthouse 均未运行；不继承旧日检认证本轮，也不宣称点击、LCP 或 INP 改善。

继续处理容量缺口需要新增可验证的完成/引用/恢复证据，或不影响活动任务的维护窗口。达到实际容量目标且复核运行状态之前，不提前关闭 GET-564。恢复已迁移资料时，先核验并挂载私有卷，复制回新的内置位置并完整校验，再替换兼容链接；保留共享 Git 历史依赖与 Keychain 项目。
