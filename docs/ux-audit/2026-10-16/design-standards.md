# 什么是好的博客与 Space 体验

2026-10-16补充研究与判定说明。此文解释既有固定量表，不改变权重或已记录分数。96+是目标，不能由实现者自报，也不等于真实用户满意度或全站无障碍合规认证。

## 研究依据与适用边界

W3C的目标尺寸AA规则为24×24 **CSSpx**，并允许间距、等价入口、行内链接等例外；它不是“所有按钮必须44px”的规定。本项目将重要触控动作44px作为更高的体验目标，空间投影后仍实际量测。已有JSON中`physicalFont`/`fontPhysical`仅指投影后的浏览器视口CSSpx，**不是设备硬件像素**。[W3C目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

焦点可见还需要避免被页面层完全遮盖。弹层、固定导航与HUD要用实际焦点与命中验证；只有DOM尺寸或CSS数值不足以判断。[W3C焦点不被遮挡说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)

“减少动态效果”需要覆盖用户触发的非必要位移/缩放；交互动画可关闭属于AAA条目。本项目另要求运行时改偏好立即生效、后台与离屏资源停止；后两项是本项目工程要求，不冒称该条规范逐字要求。[W3C交互动画说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

NN/g的渐进披露原则支持先呈现主要任务、再按需展开次级复杂性；状态可见性原则要求及时、清楚地反馈当前操作。用于判断首页主次、真实pending/error/stop，而不是据此删除原有功能或装饰成假在线。[渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)、[系统状态可见性](https://www.nngroup.com/articles/visibility-system-status/)

动画优先考虑transform/opacity，其他属性要观察布局和绘制成本。它是性能路径选择，不能保证“用了transform就流畅”，也不能替代真实设备数据。[web.dev动画性能指南](https://web.dev/articles/animations-guide)

三个产品/博客参考的具体机制另见[首页方向研究](homepage-directions.md)：swyx身份与真实作品、Josh Comeau具体阅读起点、Bruno Simon空间探索与恢复入口。没有复制整体视觉，也没有声称审完这些站点性能或无障碍。

补充文字对比判定：普通文字最低4.5:1，大字有3:1门槛；不能把2.957四舍五入成3。计算使用浏览器前景/背景与透明度合成，不拿抗锯齿边缘颜色替代CSS颜色。本项目书封DOM文字保守统一以4.5作为目标，仍区分项目目标与规范大字例外，不自动宣称全页合规。[W3C文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 固定判定表

下列“好/坏”是本项目的设计判断与验收约定，不是外部研究已经替本博客证明的结果。

| 对象 | 好的标准 | 坏的征兆 | 实际验收 |
|---|---|---|---|
| 首次进入 | 身份、真实作品和主要去向可理解，背景准备与前台引导并行 | 先看协议版本、假进度；强迫读完介绍才能浏览 | 新会话与回访、首帧/skip、失败降级、主入口动作 |
| 按钮/链接 | 名字说明结果，视觉主次与任务频率一致 | 所有按钮等权发光；图标仅靠猜；打开后名称/意图变化 | 名称、中心与边缘命中、实际动作、键盘Enter/Space语义 |
| 边框/注意力 | 区分输入、选择、承载面与活动窗口 | 描边+内描边+光晕+阴影叠加，装饰比内容先被看到 | 同一主题前后实拍、灰度层级、真实focus态辨识 |
| 阅读与电脑内容 | 主正文舒适、摘要真实、帮助选择的状态可读 | CSS写16但3D投影变小；关键限制只剩7px；大图把动作推走 | 投影后字号、行长、对比、200%与320/390/横屏、滚到底 |
| 状态与错误 | pending由真实请求驱动，能停止/重试，失败保留输入 | 复制失败仍“成功”、假“已送达”、无限busy、重开丢草稿 | 拒绝/空响应/中断/迟到/关闭/重开/新请求隔离 |
| 窗口 | 最大化、恢复、排列/总览均兑现名称；原内容连续 | “并排”后仍遮住一窗；放大后控件出界；重排丢原笔记 | 2/3/4窗实际动作、hit、focus、同DOM/草稿 |
| 动画 | 解释交接与操作结果；稳定目标可点击 | 每段都漂浮/弹入；按钮悬停跑开；运行期reduce无效 | normal/reduce及中途切换、hidden、离屏、取消/反向操作 |
| 空间环境 | 光线/材质/比例协调，猫有漫游与休息，不妨碍阅读 | 装饰看似可点却无动作；动物穿模；所有物件持续抢眼 | 场景首帧/换景/视角、quiet/hidden/阅读暂停、碰撞边界 |
| 墙壁/家具 | 以真实照片与有层次材质承载作者个性 | 假荣誉/假内容、无意义标签、为显“高级”多铺一层边框 | 内容来源、场景实拍、可操作性一致、失败不阻断 |
| 手机布局 | 次级内容可滚动或披露，主要动作与输入留在可达范围 | 缩成桌面微缩图；只把按钮放大后挤掉正文 | 320/390/568×320/844粗指针，滚动、长内容、焦点位置 |
| 性能与恢复 | 首屏可用、资源按真实可见性进入和释放 | 透明/隐藏的canvas仍运行；背景准备失败后黑屏 | 未交互/离屏/后台/reduce/离页、fallback、资源日志 |
| 证据 | 源码冻结→实际动作/图→独立复核，遗漏明确列出 | 把旧图/调度成功/一次绿灯/实现者96当完成 | source manifest、case元数据、原始日志、review closure |

## 本轮具体反例

E9产品合同揭示：空demo却出现“测试预览”并打开首页，是有名称但结果不真实；正确做法是没有地址就不生成该可选入口，保留其他真实动作。不能把多一个按钮当功能丰富。

844×390产品初开时，选择器与探索占满正文首屏，虽然能滚到内容且所有按钮达44px，标题/介绍仍不可见。这里的好标准是短横屏同时保留可操作选择和产品身份/至少一行介绍，次级探索低于正文注意力；不能只用isVisible、无横溢出或目标尺寸证明布局有品味。这是本产品的入口层级标准，并不要求所有页面把全文/所有动作塞进首屏。

## 如何计分

沿用control/scorecard固定六维：任务清晰20、命中与键盘25、状态恢复20、视觉15、动效性能10、响应连续10。硬门槛失败先修；缺设备/语言/主题/状态证据保留`unverified`与`null`。专家视觉范围分、合成测试和真实浏览器动作分别记录；它们都不能自动替代真实用户研究。当前场景是风格化实时3D，不能称为摄影级真实或已达到99分。
