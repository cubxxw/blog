# 江南夜雨第二版：本地验收

作者澄清保留 OS，希望电脑更像真实物件。此次移除房间底部三枚外置入口，把原工作区直接投影进 Mac 屏幕，默认显示首页，点击后放大使用。旧木船从背景中独立出来，缓慢经过河面；雨线加密、加长，近层下降速度增加。

## 定向结果

- `npm run bear:test`：255 项通过，包含屏幕投影、船的连续路径和旧状态边界。
- `npm run typecheck`、`git diff --check`：通过。
- 最终夜雨、旧边界、资料/书库、相片恢复浏览器组：68 项通过，覆盖桌面与手机。
- 此后针对缩回途中再次打开、单次/重复搜索快捷键、近景中断追加动态回归：8 项通过。使用当前显示矩阵的四角作为反向起点，避免固定终点造成跳变。
- 房间刷新后显示首页、工作区内刷新保留书库/收藏/阅读位置的补充组：8 项通过，原笔记内容保留。
- 阅读、窗口排列、产品/书架、偏好/联系、壁纸及夜雨组：78 项通过。这组与上组有重叠，不将两组相加为独立用例数。
- 原编辑器、正文、反向选区保留；从相册或笔记返回房间，再打开电脑，使用同一 DOM 节点。
- 独立复核通过：单次及重复搜索快捷键在放大途中关闭搜索后，焦点回到可用 Dock；近景中途暂停时，相机与真实屏幕同步结束，最大边缘误差 0.0195px。
- 正常动态、安静模式、减弱动态、横向平移、改变视口尺寸以及缺少画布恢复均有覆盖。两次重复快捷键、暂停时投影错位先以浏览器回归复现，再修至通过。

本地渲染使用 `netlify dev`。需要内容、接口故障和恢复状态的合约用例沿用仓库固定响应；画面、DOM、实际点击和焦点处理在浏览器执行。线上部署与整站检查须单独核对，不由上述局部结果替代。

## 上轮整站失败的修正

上轮 [39507440595](https://github.com/cubxxw/blog/actions/runs/39507440595) 的浏览器组为 778 通过、10 失败、24 跳过。失败对应五个用例在两项目中的重复结果：三个旧浮动导航合同，以及两个首次切换至三维场景的五秒等待。

旧浮动导航合同现在于导航前明确选择原三维场景，保留原有关闭、地图、触控和导航检查。电影场景通过 OS 菜单返回的路径继续单独验证。

跨渲染器的主题提交条件等待改为 30 秒，仅调整这两个等待点，用例总预算为 90 秒。真实强制 SwiftShader 的 Chromium 本轮冷切换耗时 15093ms，随后主题提交、近景焦点、单渲染器及返回电影房间均通过。未提前提交未就绪场景，也未改变全局断言等待时间。
