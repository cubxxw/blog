# 电脑浏览器、音箱音量与首页项目直达

本轮延续本地咖啡馆版本，修改保留在 `codex/space-night-cafe` 工作树。没有提交、推送或部署。

## 博客首页的实际问题

首页项目卡片有两套不同的目标：底部“打开”已经使用 `products/url.html` 解析的官网地址，图片、标题和正文共用的主链接却固定为 `/projects/#项目ID`。因此同一张卡片不同区域的行为不同，点击主体还会先加载 Space。

主链接现在复用同一个 `$productUrl`。英文与中文首页共 16 个卡片入口直达对应官网，保留 Leafhour、IMStage 的语言地址；只有源码入口的项目直接去 GitHub。14 个独立“打开”链接和 16 个 GitHub 链接保持一致。没有增加点击脚本，也不依赖 JavaScript 完成跳转。原来的 Space 导航仍是独立页面入口。

## 浏览器与项目目录

电脑增加 Browser 应用，入口在桌面、Dock、“文件”“前往”菜单与应用搜索中。默认仍能看到整台电脑和后方房间；需要时可放大屏幕。主页使用现有项目目录生成八个官网收藏，显示本地预览图、名称与域名，不额外请求远程图标。

作品目录改为有预览、简介、阶段和直接访问按钮的列表。查看介绍与访问官网分别可操作，不必先展开详情才能到官网。

`data/products.yml` 的 `browser_embed: true` 表示允许在电脑中浏览，并随页面目录输出为 `embed`。默认不嵌入未知外站。2026-10-22 实际响应检查中，Leafhour、IMStage、Roamorrow 未下发禁止嵌入的响应头，已配置内嵌；capri 和 GitHub 明确下发禁止嵌入的响应头，保留原生新标签页链接。三个 `cubxxw.com` 子域在本机检查时返回 403，本轮保留目录原地址并使用独立标签页，未将其归因为站点下线。

网站能否嵌入由其响应策略决定，参见 [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) 与 [frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)。没有代理抓取网页、移除响应头或扩大设备权限。浏览器保留官网原生新标签页入口。

地址栏验证使用现有 `safeURL`，拒绝脚本、带凭据和异常控制字符的地址。站点历史支持主页、前进与返回；它不是跨源网站内部每一页的历史。第一方 Space 子页面不会再次启动桌面、音频和 WebGL，内嵌博客跳到 Space 时转为独立页面入口。浏览器自己的链接由 Browser 持有，不交给背景阅读层截获。

显式再次访问同一官网会更新当前页面；从 Dock 恢复则保留当前页面。电脑正对屏幕时，原来的桌面节点使用真实投影矩形对应的平面表面，仍保留外部三维电脑。整台电脑与放大屏幕之间切换不重复挂载桌面，网页内当前状态不会因此重载。离开电脑回到三维房间时，跨源网站内部页面、登录和表单状态的完整持久化不在本轮验收承诺中。

## 音箱

独立音乐声道默认从 `.3` 提高到 `.6`，唱片面板中提供 0–100% 滑杆与当前百分比。设置使用 `space:cafe:music-volume:v1` 保存在本机；0 是有效设置，切换唱片和刷新后保留。滑杆更新已有 gain，不重建音乐或雨声音源，雨声响度独立。调整期间更新原滑杆节点，保留拖动与键盘焦点。
