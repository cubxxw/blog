# 连续使用走访：离座后还能接着用

本轮沿用本地咖啡馆版本，按访客的一段连续操作检查：打开唱片和音乐、进入电脑、打开网页并输入内容、离座开灯和风扇、看书与窗景，再回到电脑。测试中用真实鼠标和键盘操作浏览器，跨域网页采用受控测试页固定结果；实际本地博客另做显示与离座返回复核。

## 发现与修正

| 细节 | 修改前 | 修改后 |
| --- | --- | --- |
| 起身后回到网页 | 内嵌网页重新加载，草稿与按钮状态丢失 | 原网页保持连接，输入和页面状态保留 |
| 打开网页时的反馈 | 白屏期间只有通用提示 | 轻量加载线与站点名称；等待较久时提供独立标签页的选择 |
| 在地址栏重复输入当前地址 | 提前返回，没有重新请求 | 明确重新访问；站点历史不重复增加 |
| 重试入口 | 只能改地址或绕回主页 | 提供重新打开站点按钮；主页时禁用 |
| 网页状态栏 | 本地站点出现重复域名 | 同源网页显示实际标题，跨域站点显示名称与域名；长文字省略 |

## 网页为什么会丢失

原桌面在平面电脑屏幕与三维显示层之间转移时，会先移除节点，再挂入另一层。输入框本身仍在，嵌入网页的文档却会重新加载。因此只检查桌面笔记保留，还不能证明浏览器也可连续使用。

新增 `dom-transfer.mjs`，在相同文档、双方已连接且浏览器支持时，使用 `Element.moveBefore()` 保留 iframe 文档和交互状态；初次插入及不支持的情况保留普通 DOM 行为。这个 API 的状态与限制参见 [MDN moveBefore](https://developer.mozilla.org/en-US/docs/Web/API/Element/moveBefore)。

CSS3D 适配器通过 `preserveElement` 显式选择保留页面元素，默认销毁语义不变。Jiangnan 退回普通工作区前先恢复原应用节点，再移除旧场景，支持原生无损移动的浏览器中，模拟图形场景失效也不会丢失网页草稿。

## 兼容路径

不支持无损移动时，访客打开网页后再离座，实际工作区停留在原来的节点位置并隐藏，物理屏幕改为安静的山景待机画面。待机时间沿用房间的魔法时钟。坐回电脑后，揭开的是同一个网页。

尚未打开网页时仍展示原来的工作区主页。兼容分支不生成第二个网页，也不把原窗口或 Dock 留在房间上方。独立审查曾发现子层的 `visibility:visible` 会覆盖父层隐藏，新增回归复现后，已将这条可见样式限定到实时预览。

浏览器只读检查接口会隐藏部分原生方法，不能以接口中的 `typeof element.moveBefore` 直接判断真实引擎能力。本轮曾据此误判内置预览；随后以实际分支状态与页面表现核对，当前内置预览走原生路径。兼容路径通过禁用该方法的独立桌面与手机场景验证。

## 验证边界与证据

原生路径与兼容路径都验证了输入、按钮状态、开灯、风扇、书架、窗景、离座返回，以及音乐和雨声沿用原音源。受控网页的文档请求计数不因离座增加。原生路径另做了 `webglcontextlost` 故障注入，确认普通工作区回退后草稿仍在；这属于模拟故障，不代表真实显卡故障验收。

声音连续性检查覆盖日常离座与返回。图形场景完全销毁时的旧音频清理行为没有扩大修改；不支持无损移动的旧引擎，在完整场景销毁后的跨域网页状态也不作同等保证。外站真实登录、支付、上传与导出不在本轮验证范围内。

`npm run bear:test` 通过 435 项；最后兼容代码的定向检查通过 15 项，类型检查、生产构建与差异检查通过。最终浏览器与兼容分支 10/10 通过，经典电脑、看窗及音量复核 26/26 通过，共 36 个独立场景用例。前后截图、失败记录、复核结果放在本机 `/Users/xiongxinwei/.gstack/projects/blog-space/designs/human-journey-20261022/`。
