# 经典 Mac 动漫桌面

作者否决了“作品工作台”和“私人书房”两版首页，明确要求：模拟真实的老版 macOS 动漫桌面，降低认知负载，并看到整个电脑屏。旧方案仅留在本工作树 `.netlify/workbench-design/a.html` 与 `b.html` 作为被否决的方向，不进入产品实现。

新的识别顺序是完整显示器、顶部菜单栏、桌面文件夹、Finder 窗口和 Dock。默认内容是“我的空间”的文件夹窗口；作品、文章、相册、书架、笔记和个人简介均为现有真实应用，不再用欢迎立方体、宣传标题或二次“进入空间”门槛。物件轮廓与色彩采用柔和插画处理，保留 Mac 既有的位置和操作惯例。

参考 [Infinite Mac](https://infinitemac.org/) 的真实历史系统、[Apple Aqua 文档](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/OSX_Technology_Overview/CocoaApplicationLayer/CocoaApplicationLayer.html) 的一致布局与行为，以及 [Apple 的 Dock 操作说明](https://support.apple.com/en-gb/guide/mac-help/mh35859/26/mac/26)。采用有 Dock 和红黄绿窗口按钮的早期 OS X 语法，视觉稿位于 `.netlify/workbench-design/retro.html`。这是风格复现，不声称运行实际 macOS。

## 内容与操作

Finder 首页用有文字的文件夹呈现六个已存在目的地，首屏无需阅读长介绍。作品应用保留真实目录、产品详情与精确 payload；可从目录打开 Leafhour、capri（实际 ID 为 talent-signal）等项目。个人简介继续使用现有模板和全部深链接。未知状态、活动、位置与产品关系不补造。

菜单里的每个可点击项必须连接已有操作，暂不实现的系统能力不冒充真实功能。关闭、最小化、最大化、拖动、窗口切换、搜索、笔记、阅读、照片、深浅主题、Product Lab 和返回咖啡馆继续可用。不能破坏原笔记节点、选区和手动布局。

## 电脑屏的呈现

作者已确认完整显示器方案，并要求进一步打磨空间与真实后景。默认在完整物理显示器里使用同一套 DOM，同时保留铺满浏览器的可读桌面。两种视图通过“显示”菜单切换，均复用同一原始工作区；没有截图替身或第二份笔记。屏幕模式变化时，只调整可用视口和图形相机，不重建应用。

电脑视角固定在椅子前的坐姿位置，背景来自同一间实时咖啡馆及窗外江南雨景。景深按实际场景深度处理，显示器、底座与真实交互屏清楚，后面的木作、窗景、船和雨带柔和虚化。手机和横竖屏切换只改变视野，不把相机退到椅子后。奶白机身、内框、键盘边缘、接触阴影和轻微使用痕迹统一打磨。完整显示器模式继续播放受限帧率的雨、船与风扇，遵守减少动态、安静模式和页面隐藏设置。

完整显示器模式正对屏幕，使指针、拖动与滚动落在真实屏幕上，边框不被裁切。窄手机保留明确的放大方式，避免为了露出显示器而强迫用户阅读缩成几像素的文字。系统全屏与电脑屏放大是两个独立动作，文案分别命名。

## 视觉与验收

桌面壁纸复用已有插画山水，文件夹与应用图标统一轮廓、柔和亮面和清楚的短文字。Finder 标题栏、侧栏、文件区和状态栏有明确层级。桌面、窄屏、短横屏与深色均单独看实际截图。

功能验收包含：一眼可辨认的菜单/Finder/Dock、六个精确目的地、真实产品与文章、个人简介深链接、编辑与窗口状态、两种屏幕呈现的来回切换、显示器完整投影、鼠标拖动映射、原生全屏、对话框与焦点恢复。审美取舍按作者反馈判断，不用测试数量代替。
