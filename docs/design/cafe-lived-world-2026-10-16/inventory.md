## 按影响排序的十项

### LW-01　光源、遮挡与接触：室内／露台／六景

- **源码事实**：四盏吊灯均为同参数 PointLight，没有开启各自投影（`world-cafe.js:158–169`）；投影主要来自一盏 DirectionalLight。其 shadow camera 覆盖 26×26 场景米、map 为 1536²，名义采样间距约 1.69cm（不是屏幕像素）。`shadowMap.autoUpdate=false`（`:18`），五张桌椅的阴影另由固定放射状平面近似（`:107–111`）。环境反射是一次 64px 室内捕获，捕获时隐藏 outdoors，发生在猫与实时 DOM 加入之前（`:327–337`）；换景只改天空／雾／日光强度，不重拍它（`:270–275`）。
- **视觉风险**：灯罩下方虽变亮，桌边、椅腿和人体尺度的遮挡未必服从局部光源；家具底下可能像统一黑晕。不同场景的金属、釉面和户外水面可能仍带同一室内反射。以上因果简化确实存在，洗白、浮空或错误反射是否显眼仍待实看。
- **高影响修法**：先确定白天窗光／雨夜吊灯各自的主光与柔和补光，校准桌椅／墙脚／杯碟接触；对近处遮挡做有范围的阴影或接触近似，远处保留便宜方案。只在确实需要时为少量主灯增加投影；反射应区分室内与户外／场景变化，不先开启所有光源每帧投影或全场持续反射。
- **实际检验**：同一桌边位置 zen→rain，看杯、桌沿、椅腿和墙脚是否同时解释得通；露台看金属／水面是否像室内镜像。停住时阴影不漂，切场景后明暗与反射一致。此项通过不外推 FPS、六景全部材质或动态猫投影。

### LW-02　猫缺少可发现的互动路径：室内

- **源码事实**：`world-cat.js:8` 把猫 anchor 加到 scene；`world-cafe.js:393` 的点击射线只查询 room.children，猫不在查询树中。`:394–407` 仅分派电脑和带 inspect 标记的物体；controller `cafe.js:124` 只接受 coffee／books／spines。resident 返回 API 也只有 ready／update／dispose／loaded／snapshot（`world-cat.js:105`），没有用户动作；模板只有咖啡／书近景入口（`space/cafe.html:42–46`）。这是现有能力缺口，不是未发现隐藏按钮。
- **视觉／交互风险**：猫能出现在画面、能走，但人点它没有对应回应；用户很难把它理解为这个场所的住客。光给全屏画布加 pointer 不能构成可理解的猫互动。
- **高影响修法**：给同一 resident 建立明确动作入口，例如“和猫打个招呼”，再让可信物体点击与可聚焦的普通按钮调用同一受控动作。先用已有 Head／rig 能力做短暂抬头、看向或短回应，再回原状态；不要求自动追逐用户或抢相机。未加载／休息／安静模式应有准确、克制的反馈，不能显示假成功；这些入口和动作目前尚不存在。
- **实际检验**：桌面实际点猫、手机实际触猫、键盘激活对应入口均得到一次可辨回应；同位置拖动仍只转视角。墙后／被挡住的猫不可穿物误点；弹窗、工作区、退场和 dispose 后不触发。动作不清空 Notes、不改变相机与阅读位置、不强制播放声音。

### LW-03　猫的停留、步态和状态发现：室内

- **源码事实**：已有 8 点连通图和 look／walk／rest（`cat-state.mjs:10–61`）；rest 的随机条件使停留约 12–22.8 秒，look 约 7.15–11 秒，起始 look 为 3 秒。朝向有角速度限制、行走会靠近目标减速，不能称完全匀速瞬移。视觉层只有原首个 idle clip 加四条腿的正弦旋转；rest 改 idle 速度与阴影 opacity，look 没有专门面向用户的分支（`world-cat.js:38,79–98`）。`lifeActive` 在 quiet、reduce、inspect、workspace、阻挡时为 false（`world-cafe.js:426–448`），后台亦暂停；`data-cat-*` 是诊断数据，不是用户可见状态。
- **视觉风险**：较长停留与单一 clip 混合可能让“在休息”看似“坏了”，脚部可能滑行；但单张静止图不能证明动画失败，GLB 自带 idle 的具体动作也不能仅从 JS 推断为零。
- **高影响修法**：先把休息／看向／回应／走路的行为做清楚，并让步幅与位移匹配；在已有骨骼上做少量有因果的头部／耳尾响应，不靠全身上下浮动。保持减速、碰撞和暂停语义；用户显式打招呼可给有限、低动态的回应或静态反馈，不能绕过 reduce／quiet 开启持续漫游。
- **实际检验**：normal 连续观察一次起步、转身、停步、休息和恢复，脚落地与位移相符；quiet／reduce 下检查状态反馈而非要求走动。离开标签页／进入工作区再回来，原地点与停留状态延续，不跳位置、不重建猫、不出现重复循环。点击回应只验新动作的命名范围，不借此声称全部动画已自然。

### LW-04　木材／灰泥／石面 UV 与物理尺度：室内及露台

- **源码事实**：oak／walnut 各一张 512² 程序木纹，同一图兼作 albedo 与 bump（`world-cafe.js:41–51`），默认 box UV 随几何缩放。地板单独 repeat 4×4；圆桌已改投影 UV 和 Lathe 倒角（`:69–84`），不能要求重做旧 20 段桌面。墙与石共用 grainMap，linen 仍只有色值。露台细缝等距 .3m（`:276–277`）。
- **视觉风险**：一条长梁、一根细腿和一块桌面可能呈现不同尺度的同一条纹；彩色条纹同时起伏会像压花塑料。墙石的同源随机颗粒难表达不同表面，露台等距长缝又强化生成感。不能仅凭“程序生成”断言必然不好看。
- **高影响修法**：按米和面向定义木纹密度、木纤维方向与端面；把微粗糙度和主要颜色变化分开，保留小范围有节制差异。对墙、石、布分别建立其表面尺度，先改善近处桌沿／墙脚／露台主通道；复用 atlas 或 world-space 规则，不先为每根梁复制高分辨率素材。
- **实际检验**：同一镜头内桌面→桌腿→梁→地板比较纹理尺度；走近再走远，无明显拉伸、贴图循环接缝或噪声闪烁。露台斜看板缝与木纹仍能理解为板材。看图确认的是这些表面，不认证全部 UV 或纹理带宽。

### LW-05　墙体、边缘与建造关系：室内／园林

- **源码事实**：室内主体是整面 west box wall、重复方梁／窗柱、两块顶板（`world-cafe.js:91–101`）；灰泥仅细噪声，墙脚／转角／木框接缝没有专门构造。窗边座、桌腿、吧台、工作桌仍多为 BoxGeometry（`:63–66,103–104,113–131`），但椅背与圆桌已有倒角。尺度采用米，座高 .48、桌高 .75、相机眼高 1.52；不能因模型感便任意缩房子。园林门是真几何洞，墙／门本体仍锐利（`:311–317`）。
- **视觉风险**：大面积均一墙面和无装配关系的锐角，让家具看起来放在一个空模型盒里；近处杯子／书的精细程度反而暴露周围断层。
- **高影响修法**：先完善可见墙脚、窗框厚度／连接、木材端部和常触边缘的光线转折；墙面应有低频且符合施工的明度变化，而非满墙脏斑。保留有意留白，不把每块空墙填海报。园林只处理近可见的墙体压顶、门沿与地面连接，不改月洞几何为贴图。
- **实际检验**：入口转向西墙、窗框侧视、工作桌侧看、园林门前各判断轮廓和接地；真实感来自可解释的厚度与关系。相机／杯／桌／椅的人尺度应统一，通道仍可走，猫和电脑点击不被新 trim 遮挡。

### LW-06　植被不能只用叶数表达真实：室内／禅庭／园林／山居／海岸

- **源码事实**：枫树已使用本地叶纹、细分树干／枝条和体积冠簇（`world-cafe.js:189–214`；`world-garden.mjs:17–35`），不是旧大叶团。仍是 6 主分枝、12 椭球分布簇；叶位置围绕簇体采样，不逐片附到枝上。`MAPLE_LEAF_BUDGET=80000` 是预算而非真实性分数。室内盆栽仍用直杆和拉伸球叶，茎端与叶心高度分别随机（`world-cafe.js:165–166`）。名为 pine 的树仍使用原枫叶轮廓贴图（`:172–174,237–249`）；海岸树冠是 9 根辐射直段（`:283–284`）。
- **视觉风险**：枫树近看可能仍像体积叶云；室内叶茎连接、松树叶形和海岸树冠可能直接暴露通用拼装。叶子更多并不修正这些生长关系。
- **高影响修法**：先做室内一株的叶柄／薄叶／盆口土面，再让松、海岸树有相符的轮廓；枫树关注主枝疏密、冠缘缺口、叶片方向与深浅，而非继续加密。保留已有本地叶纹和苔丘接地改善；无须为所有树增加风动。
- **实际检验**：桌旁植物近看茎叶相接；禅庭从室内看一棵近枫与其冠缘；山居和海岸各确认树的类别可辨。枝叶不穿明显主干，不把叶片背面看成整块纸牌；normal／reduce 都保持可信轮廓，不能用摆动掩盖错误结构。

### LW-07　岩石形状、基底与苔石关系：禅庭／园林／海岸

- **源码事实**：全部 rock() 复用一个 `IcosahedronGeometry(1,1)`、同色 roughness .9 材质，只改非均匀缩放和小角度旋转（`world-cafe.js:178,234–235`）；海岸再改共享颜色（`:283`）。禅庭／园林随机放 22 块，海岸放 12 块。苔丘已由 `mossMound()` 压扁并按支撑范围落地（`world-garden.mjs:37–40`），不能继续套用旧高球／漂浮苔丘结论。
- **视觉风险**：石头虽大小不一，轮廓拓扑、材质与分布逻辑仍相近，可能像同一个低模的复制；苔与石各自随机也可能像分散的绿垫与灰球。具体悬浮／穿透未实测，不能凭随机摆放就判已发生。
- **高影响修法**：用少量有辨识度的非对称轮廓族、断面／圆磨差异与朝向，建立部分埋土的稳定基底；苔应沿接地／背阴关系包覆而非均匀铺撒。近水的湿暗变化应遵循接触区，不能给所有石头同一高光。无需先引入大量外部模型。
- **实际检验**：露台看近、中、远三块石，在微移视角时形状不似同体复制；落点有重量，苔石边界相接且不悬空。海岸与禅庭不应只差一种纯色。仅验证选定石群，不扩充成“全岩石已真实”。

### LW-08　远山的峰线、层次和雾：山居／湖畔／禅庭／园林

- **源码事实**：每座 mountain() 都从 16×8 PlaneGeometry 以同一近对称轮廓公式起伏，仅宽高／色／位置不同，深度由 sin 扰动约 ±1m（`world-cafe.js:253–259`）。山居是 3×8 片同宽山、湖畔 9 片、禅庭／园林各 2×6 片（`:281,287,319`）。湖山中心 z=−102，而常规雾 far=95，默认相机 z=2.45（`:272,281,357`）；默认视角山很可能被雾冲淡是条件推断，尚未看图证明。
- **视觉风险**：重复峰形与等距成排容易像舞台纸片，统一单色难表达体积；雾可能使本应支撑“湖与远山”的主体消失。
- **高影响修法**：先打散峰线对称与排列，做少量前后关系明确的山脊和山谷，按距离调整明度／饱和度／雾；近处需要体量，真正远处可继续用轮廓。校准湖山的距离与雾，不先堆多边形、无限远景或任意云层遮挡。
- **实际检验**：山居／湖畔默认与露台同方向各看一次；横移时近脊与远脊有视差，峰线不重复，雾保留必要轮廓。禅庭／园林的背景不抢近树与月洞。画面可接受才保留平面简化，不以“用了体积模型”替代审美验收。

### LW-09　岸线、水面与雨街的空间因果：露台／海岸／湖畔／雨夜

- **源码事实**：coast 和 lake 使用同一 160×100 的平面水体，起点边界 z=−15，只改色和背景（`world-cafe.js:261–264,279–284`）；sin 波只改顶点 Y，未更新法线（`:441`），材质用 metalness .35／roughness .2。scene.environment 来自室内捕获，水体没有独立外景反射。雨夜 7 栋等距方楼、每栋同一 2×3 亮窗格，900 个 Points 竖直循环，没有雨水落地／窗面关系（`:289–297,442`）。
- **视觉风险**：水岸像两块色板拼接，波动几何与高光未必一致；湖海可能只是换色。雨街可能像复制窗口和飘浮粒子，灯光与湿地没有同一因果。
- **高影响修法**：先做一段主视线岸线／水陆接触和符合外景的反射／法线响应；海岸与湖畔分别确定波形、岸边和远景关系。雨夜减少无意义等亮重复窗，用少量有理由的亮窗／暗窗与近地湿亮层次，雨滴表现保持克制。pause／reduce 下仍应通过静态材质成立。
- **实际检验**：露台斜看水边，normal 下短观察一次波与反光，再 quiet 看静态水陆边界；rain 比较灯下路面和暗区、室内窗边与街楼。不得用“图里有水／雨点”认定真实，也不要求为了截图增加持续绘制预算。

### LW-10　真实生活内容与使用关系：室内／吧台／露台

- **源码事实**：已有作者四本作品和六本旅行书、熊野实拍相框、主杯及空杯存放（`world-details.js:23–61`；`world-cafe.js:121–142`），内容不是全占位。两张桌的 `tableBook()` 都取第一本自著；其余物件为重复杯、罐、规整设备／键盘。壁面和露台没有独立生活内容（`:91–104,113–156,276–277`）。
- **视觉风险**：即使每个物件更细，复制的摆放和缺少使用关系仍会像样板间。墙空不是缺陷本身，随意增加道具也不能证明有人生活。
- **高影响修法**：只选两三个符合作者实际内容的生活锚点，例如不同在读书、夹在书中的纸签、已有旅行照片的合理展示、杯与座位的使用关系；让主要动线和视线有理由。书目／照片沿用真实来源，允许留白；不编造奖状、客人故事、店史、店铺营业信息或陌生收藏。
- **实际检验**：从默认入口→读书桌→工作桌→露台，能说明“谁在这里做什么”，且主角依旧是咖啡、书、住客猫和作者。物件落在可用表面，座位能坐、通道可走、电脑可点；新增生活细节若挡猫或增加假互动则不通过。

## 父任务可复用的有界检验路径

以 `/projects/` 的咖啡馆入口为主；中英实际路由沿原站点生成，不在此虚构 query 开关。六景从 `[data-cafe-picker]` 打开后选 `[data-cafe-theme]`，其真实 value 分别是 `zen`、`garden`、`coast`、`mountain`、`lake`、`rain`；露台为 `[data-cafe-outside]`；杯近景为 `[data-cafe-inspect="coffee"]`，书近景为 `[data-cafe-inspect="books"]`，书脊为 `[data-cafe-bookzoom]`。先对同一 viewport／同一位置看室内→zen 露台，再按对应条目选场景；不同镜头不能冒同位置材料比较。

猫当前没有可激活 selector；现有 `[data-cafe-quiet]` 只切安静模式。`[data-bear-workspace]` 的 `data-cat-loaded`／`data-cat-active`／`data-cat-state`／`data-cat-pose` 可辅助解释暂停、加载与移动，不能当用户反馈或实际点击。新入口实现后才登记其真实 selector 与命名动作，不能预先授予键盘／触摸通过。

至少保留普通桌面与手机各一条实际路线；normal 检查自然行为，reduce／quiet 检查可理解反馈与静态构图。先核光线与猫，再按实际画面选材料／墙或自然景观中的高影响小批；不按十条全量重做，也不以拍更多图增加“功能通过”数量。

- `world-cafe.js:338–343,463–468` 移动并归还原 windows／snap／bottom／menu，不重建 BEAR OS；`desktop.js:491–495` 接回原窗口。真实回归应保 Notes 原 DOM／草稿／选区、阅读位置和返回相机，不只查看新装饰。

- 本文件只给建议，不改旧审计分数；实际截图、动作与测量未出现前保持 source-only。每批只能据其真实范围验收，不能宣布整个世界或所有按钮达到 96／99。
