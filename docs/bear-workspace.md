# CUBXXW OS：公开内容与访客工作区

CUBXXW OS 默认呈现作者的文章、产品和旅途，访客可以在当前浏览器保存笔记、收藏与窗口布局，也可以交给 BEAR 一项有步骤、有结果的小任务。Hugo 提供公开内容；浏览器管理私人工作区；模型与 Immich 的连接配置留在服务端。

本轮功能与验收状态见 [2026-10-13 验收记录](acceptance/2026-10-13-bear-os-evolution.md)。真实模型网络及公开目录工具已完成线上冒烟；Immich 相册尚未配置，Docker live 执行尚未验收。

## 入口与导航

网站导航只保留「文章」与「空间 / Space」。`/projects/` 与 `/zh/projects/` 默认进入真实三维 Space Café：先进入房间，再行走、拖动看四周，或走向电脑。CUBXXW OS 是房间中的悬浮界面，离开电脑后继续漫游。禅庭、园林、海岸、山居、湖畔、雨夜书屋共享房间和桌面应用，切换实际室外模型与照明，默认禅庭；OS 菜单和设置也提供换景及返回咖啡馆。场景切换不重新挂载应用、不修改笔记、草稿、收藏、窗口或助手任务。刷新和语言切换保留风景及房间/电脑模式；内容深链和 Product Lab 优先打开原目标。三维版与会话恢复在 2026-10-15 获得作者发布确认，纳入主线交付；此前的图片咖啡馆回撤记录保留在本地验收文档中。

底部 Dock 保留常用应用，OS 菜单收纳所有应用、搜索、窗口管理、设置和 Product Lab 切换；桌面不摆放应用图标和顶部工具栏。Product Lab 保留双向切换，文章原始路由、博客首页和 Travel 继续可访问。房间、家具、电脑、庭院植物、水面和远景由 Three.js 模型构成，真实 DOM 应用通过同一相机的 CSS3DRenderer 放进房间。没有全屏背景照片；原图片版本的 [资产记录](space-cafe-image-prompts.json) 仅保留为历史设计参考。三维代码、验证方法与交付边界见 [本地验收记录](acceptance/2026-10-14-space-world-local.md)。

「关于我」窗口包含个人介绍、五段公开经历、完整履历与阅读地图。HTML 由 `space/profile.html` 从现有 `identity.json`、`about-story.yml` 和 About 正文生成，与原始公开资料共用数据源。访客无需离开桌面阅读，也可以从个人介绍打开联系窗口。关闭 JavaScript 后，原生 disclosure 与资料链接仍可用。

部署时，旧 `/about/` 与 `/zh/about/` 强制跳转到对应空间入口，`profile=about` 使没有锚点的旧链接也打开个人介绍。旧 `#identity`、`#story`、`#start-here` 等锚点继续定位窗口内的内容；旧 Start Here 链接直接进入阅读地图。原 About HTML 保留为静态兼容输出，canonical 指向空间并退出站点地图，生产导航不会再产生独立 About 入口。

桌面菜单和欢迎引导使用 CUBXXW OS 字标，BEAR 继续是任务助手。访客存储键、窗口标识和产品深链保留原有协议，以便已经保存的笔记、收藏和布局继续使用。

发布探针对这种迁移继续验收旧入口：只有已验证的 `noindex` 页面、其声明的同源 canonical，以及产物中实际存在的目标页面同时匹配时，才接受路径变化。目标的 SEO 元数据和资源仍须与已验证产物一致；任意改向、缺失目标和错误元数据继续阻断验收。

2026-10-14 入口合并的本地验收覆盖双语导航、反复展开档案、原生旧锚点、访客笔记、双向视图、深色模式和手机操作，浏览器没有运行异常。`npm run bear:test` 的 125 项检查、发布与探针的 20 项检查、现有工作区的 21 个浏览器流程，以及定向 CI 浏览器的 5 个流程均通过；生产构建、产品整合和生成 SEO 检查通过。新增回归入口是 `scripts/space-profile.browser.mjs` 和 `scripts/space-profile-route.test.mjs`，本地截图与回执在 `output/playwright/space-profile/`。线上发布仍须以对应提交的 CI 和部署验收为准。

宽屏保留多窗口、拖动、缩放、边缘吸附、并排、最小化与恢复。欢迎入口重新打开欢迎窗口，保留其他应用与已有位置。咖啡馆中桌面暂时不可聚焦，打开电脑恢复原有窗口；刷新继续当前工作。文章目录也记住筛选词与分类。

手机固定显示空间、文章、产品、AI 向导、设置五个目的地，另有 OS 菜单；“所有应用”打开可搜索 Launchpad，完整展示 11 个应用：`welcome`、`products`、`reader`、`photos`、`map`、`books`、`notes`、`contact`、`terminal`、`agent`、`settings`。不需要横向滚动 Dock 才能发现笔记、书架、联系与设置。

搜索应用、产品和文章使用菜单内搜索或 `⌘/Ctrl+K`。OS 菜单也提供搜索与 Launchpad。搜索无结果时可清空关键词或浏览所有应用；方向键移动结果焦点，Enter 打开，Escape 先关闭弹窗或菜单并恢复触发按钮焦点。编辑 input、textarea 或 contenteditable 时，Escape 不会误最小化窗口。

窗口控件保留彩色按钮，实际点击区域桌面至少 28px、手机至少 44px。窗口采用经典浅灰外观，桌面提供青绿、暮蓝和鼠尾草三种纯色。浅深色、减少动态效果与减少透明度分别提供对应样式。

## 语言与入场动效

设置里的「中文 / English」切换到 Hugo 的实际对应路由（默认英文是 `/projects/`），保留查询参数、锚点、笔记、留言草稿、收藏、主题与窗口布局。显式语言地址优先，已打开的文章继续显示原文，其他语言的收藏仍可在收藏目录找到，不自动改写文章链接。语言切换返回设置，不重复进入引导。保存失败时保留当前页面，并允许导出内存中的工作；会话存储受限时使用随跳转传递、随后立即移除的恢复标记。

进入咖啡馆与走向电脑使用三维相机的连续移动。电脑界面保留在场景中，屏幕周围仍能看到房间；「回到咖啡馆」或非编辑状态的 Escape 离开电脑。WASD / 方向键行走，拖动视角，E 走向电脑；手机用方向按钮与拖动。减少动态效果模式跳过自动镜头移动，保留用户主动行走。家具阻挡行走；单帧时间上限避免后台恢复后穿墙。切换标签页或进入 Product Lab 后停止绘制，恢复时调整视口。模块或 WebGL 失败时恢复原 DOM 工作区，笔记仍可编辑；GPU 上下文丢失不会让镜头或按钮永久卡住。语言切换同时保留场景和房间/电脑模式。

新增定向验收 `scripts/space-entry.test.mjs` 和 `scripts/space-entry.browser.mjs` 覆盖真实双语跳转、工作区内容保留、16 组语言/尺寸/主题组合、手机点击区域、菜单焦点与动画释放。截图保存在 `output/playwright/space-entry/`。

## 有限任务与逐操作审批

空间助手由客户端任务循环与服务端官方 DeepSeek Harness 模型适配器组成。每项任务最多 **6 轮模型请求、12 次工具调用、120 秒总预算**，调用方只能缩小上限。三个文本 AI 入口（空间、首页、文章）统一使用 `deepseek-flash`；服务端凭证为 `DEEPSEEK_API_KEY`，Messages 地址默认 `https://api.deepseek.com/anthropic`。请求不能选择 provider、model、URL 或工具集。

Dock 或 `⌘ / Ctrl J` 唤起非模态输入卡；开始任务后展开右侧结果栏，手机上使用剩余屏幕。操作记录默认收起，需要追加笔记或执行命令时自动展开具体预览，等待用户确认。Dock 状态来自真实任务事件。

文章和产品提供直接提问入口；文章选中文字后可解释该段。预填问题不自动发送，公开资料引用与选文在发送时组装，点掉上下文标签会同时移除引用和选文。笔记、联系草稿和终端内容不会被当作环境上下文读取。语音仅在用户点击后调用浏览器语音识别，先填入可编辑文字，再由用户发送；不支持语音的浏览器继续使用文本。

`netlify/lib/deepseek.js` 使用官方 `@deepseek-ai/dsh-llm-deepseek@0.2.0-rc.2` 的 `DeepSeekAdapter`，将 Messages 的文字与工具事件转换为本站既有响应协议，过滤思考内容。公开网站只加载模型适配层；应用工具由本站注册和执行。Netlify 将原生 ESM 包作为 `external_node_modules` 保留，避免 `import.meta.url` 在 CommonJS 打包时失效。运行说明与官方接口见 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness/)。

本地 `.env` 与线上 Netlify Functions 环境变量都需要配置凭证；构建成功不代表线上密钥已配置。服务分别提示配置缺失、凭证失效、限流、额度不足、超时和连接失败。验收见 [2026-10-14 空间助手](acceptance/2026-10-14-space-companion.md)。

生产站点将 `DEEPSEEK_API_KEY` 保存为 Netlify Secret，只设置 production 上下文。Starter 计划使用默认 Builds / Functions / Runtime 范围；旧 `DASHSCOPE_API_KEY` 已移除。更新环境变量后需要重新部署，才能让运行中的函数读取新配置。

| 工具 | 行为与审批 |
| --- | --- |
| `search_writing`、`read_writing` | 检索公开目录，读取同源公开文章的有限纯文本 |
| `list_photos`、`show_place`、`open_app` | 查询公开照片/地区对象，打开注册应用并检查实际窗口状态 |
| `append_note` | 展示待追加文字，每次操作单独批准；追加后检查真实笔记状态 |
| `sandbox_run` | 展示实际命令，每次操作单独批准；执行本地沙盒入口并检查退出结果 |

批准一次写入不会授权下一次写入，也不会授权后续沙盒命令。拒绝、停止、关闭任务窗口或审批超时后，迟到的批准与模型结果不能继续执行。未知工具、非法参数、重复调用与重复写入被拒绝或去重；工具失败保留错误，不记为成功步骤。沙盒结果只有得到有效的末尾 `exit 0` 标记才报告成功。

模型环境上下文只从公开 catalog 投影作者资料、文章、产品、照片与地区。浏览器笔记、草稿、收藏和其他私人工作区状态不自动上传；文章正文先移除活动内容，再返回有限纯文本。批准追加笔记时只在本地读取原笔记，工具结果不把原笔记发送给模型。操作日志显示请求、工具、审批、结果与任务终态，不存储隐藏推理。

空间助手右上角的时钟打开会话历史，可以搜索、恢复以前的对话，或单独导出为 `space-conversations.json`；「＋」开始新对话，保留之前的记录。刷新、关闭再打开、换景和中英文切换会恢复当前会话及未发送草稿。旧 `bear-agent-tasks:v1` 中仍存在的有效记录自动迁入「之前的对话」，原始存储保持完整。旧版本已经清掉的记录无法从浏览器恢复。

记录按会话、任务和各标签页草稿分别保存，避免多标签页把整份历史互相覆盖。迁移中途保存失败后，下次加载会补齐缺失记录。历史不再按最近 12 项淘汰；总记录预算为 200 万字符，超过预算或浏览器配额时保留已有磁盘记录和当前页内存，显示保存失败并允许导出，不静默删旧记录。并行编辑的草稿版本保留在导出文件中。会话仅保存在当前浏览器和同一来源地址，尚无跨设备同步；`localhost` 与线上站点的记录独立，任务历史不属于 `bear-workspace.json`。

继续对话会携带当前会话最近三轮完整的用户问题与公开回答，文字总量最多 8000 字符，并根据当前任务和服务端请求预算缩小；本地历史保留更多轮次。历史不会作为 system 或工具消息重放，也不会继承操作批准。刷新后原先执行中或等待审批的任务标为中断，不自动执行。定向迁移、并发、配额及真实浏览器恢复验收见 [会话验收记录](acceptance/2026-10-15-space-sessions-local.md)。

## 公开相册与地理地图

相册保留既有八张公开旅行照片。Immich 适配器已实现，只有作者在服务端明确配置公开相册后才发起 Immich 上游请求；空 allowlist 返回 `not_configured`，界面继续提供博客照片。当前真实相册尚未配置，不能把适配器测试写成真实相册连接成功。

服务端配置变量是 `IMMICH_URL` 与 JSON 字符串 `BEAR_IMMICH_PUBLIC_ALBUMS`。以下仅示意字段，实际相册 UUID 与 shared key 留在本机/部署配置，不能提交到仓库或嵌入页面：

```json
[
  {
    "slug": "author-selected-public-album",
    "title": "作者选择的公开旅途相册",
    "albumId": "00000000-0000-4000-8000-000000000001",
    "sharedKey": "REPLACE_WITH_AUTHOR_SELECTED_SHARED_KEY",
    "region": "japan"
  }
]
```

`IMMICH_URL` 的远程连接要求 HTTPS；HTTP 只允许 localhost/loopback。相册最多 8 个，`region` 只能是 `tibet`、`japan`、`southeast-asia` 或空值。未设置地区的相册保留未归类状态，不从照片内容或 EXIF 推断坐标。

每次读取都校验分享是对应相册的未过期 `ALBUM` 分享，且显式满足 `allowUpload: false`、`allowDownload: false`、`showMetadata: false`；缺失字段也不放行。列表查询限制在指定相册，分页游标加密并绑定相册、15 分钟后过期。图片代理再次检查资产属于该相册且为图片，拒绝任意资产 UUID、视频和上游重定向。

公开投影只返回应用所需的 ID、作者设定的标题/地区与同源代理 URL，不返回 shared key、原文件路径、EXIF、人物或 GPS。JPEG、PNG、WebP 代理会移除元数据，拒绝动画和不支持格式；单张二进制上限 4 MiB，并另检查 base64 后的缓冲响应大小。刷新、撤销分享或未配置响应会移除先前的远程投影；关闭最后一个媒体窗口会取消请求，迟到响应不能覆盖重新打开的视图。

地图轮廓来自 **Natural Earth 4.1.0 的 1:110m land**，使用 `world-atlas 2.0.2` 数据生成；来源与 SHA-256 固定在 [media-state.mjs](../assets/js/space/media-state.mjs)，可由 [生成脚本](../scripts/bear-media-geography.mjs)复现。地图采用经纬度线性投影，支持缩放、键盘平移与重置；生成脚本排除跨越整个反经线的极区环。标记使用仓库已有的公开地区中心，不能标为照片拍摄位置。数据来源与授权说明见 [world-atlas](https://github.com/topojson/world-atlas) 和 [Natural Earth terms](https://www.naturalearthdata.com/about/terms-of-use/)。

## 本地保存与运行时生命周期

笔记最多 **40000 字符**，留言草稿最多 6000 字符，收藏最多 200 条。Agent 追加会先检查整篇笔记，超过 40000 字符时明确失败、保持原笔记，不静默截断。已打开的笔记编辑器会同步工具写入结果。手动“保存到沙盒”目前最多接受 2600 UTF-8 字节，长笔记使用 Markdown 导出；继续编辑后，不会继续显示旧的沙盒同步成功状态。

需要本地执行时，在 Docker 已运行的开发环境分别启动：

```sh
node scripts/bear-runtime.mjs
npx netlify dev --offline --port 8889
```

终端通过 `open notes` 打开同一应用，`run <command>` 调用本地 Linux 沙盒。服务只监听 `127.0.0.1:8777`；随机令牌仅写入已忽略的 `.netlify/bear-runtime.json`，权限 600，不下发前端。Netlify 代理只在开发模式接受 localhost 同源请求，生产部署拒绝执行。

容器使用固定 Alpine 摘要、独立 Docker 卷、无宿主目录/凭据挂载、禁用网络，并限制 CPU、内存、进程与命令时间。它用于个人本地开发，公开多用户执行仍需独立的身份与隔离设计。

启动采用事务清理：记录容器 ID 与本次创建标记，监听成功后先写私有临时配置，再独占发布完整配置；写入、chmod、监听或容器启动失败时，回收本次 listener、临时配置和本次启动/创建的容器。配置已存在时拒绝覆盖。`close()` 的并发与重复调用共用一次清理，只删除内容仍属于本次会话的配置；进入会话前已运行的容器由原会话管理，本次退出不会停止它。清理失败会明确报错。

停止本次拥有的容器保留工作卷，但不保留其中的运行进程。Agent 的“停止”结束浏览器等待与后续工具调用，不能宣称已经终止仍在执行的 Docker 进程。本轮运行时验收使用真实本地 HTTP/文件与模拟 Docker 边界，未完成真实 Docker 执行与卷持久化验收。
