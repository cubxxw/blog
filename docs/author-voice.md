# 文章声音

为读者准备文章重点、章节讲解和问答讲解，也保留作者导语和后记。读者播放已经确认过的静态 MP3；访问文章和点击播放器都不会调用模型，也不需要新增线上后端。没有音频的文章不显示入口、不加载播放器资源。

## 默认旁白

默认使用 Gemini 的 Charon 通用音色，适合信息讲解。没有个人音色也可以整理讲解稿、生成试听，再经作者确认后加入文章。通用音色的播放器标注“AI 旁白”，与作者原声和作者个人音色区分。个人音色创建保留为可选设置；已有个人音色仍可复用，损坏的个人配置会报错，不会静默替换。

Charon 的官方定位和支持情况见 [Speech generation](https://ai.google.dev/gemini-api/docs/speech-generation#voice_options)。

## 启动

需要 Node.js 22 以上和 ffmpeg。本机安装过的项目依赖可以继续使用。

首次启动时，指向 Leafhour 已有的环境文件：

```sh
npm run voice -- --env-file /absolute/path/to/leafhour/.env
```

只读取其中的 `GEMINI_API_KEY`，不复制密钥、不更改 Leafhour 文件，也不把其他环境变量导入博客。作者工具只在 `127.0.0.1` 运行，并自动打开浏览器。环境文件的路径保存在被 Git 忽略的 `.author-voice/settings.json`。以后运行：

```sh
npm run voice
```

也可以通过 `GEMINI_ENV_FILE` 指定环境文件，或直接使用进程中的 `GEMINI_API_KEY`。密钥只在本机 Node 进程内使用，不进入 HTML、音频清单和浏览器响应。共享密钥轮换后重启工具即可。

## 创建自己的声音

在工具内分别录制或选择两份音频：10–30 秒的自然说话，以及本人读出的授权语句。工具在浏览器内转换成 24kHz、单声道、16 位 WAV，点击创建后才提交给 Google。

授权语句：我是此声音的拥有者并授权谷歌使用此声音创建语音合成模型

创建使用官方 `POST /v1beta/voices`，`type=replicated`、`store=true`，模型为 `gemini-3.8-flash-tts`。返回的个人声音 ID 存在 `.author-voice/profile.json`，以后的个人音色合成都复用它；通用旁白不会被保存或标注成个人音色。参考录音和授权录音保存在 `.author-voice/recordings/`，可自行备份。

这是 Google 项目内保存的声音。官方当前说明为最后使用起一年，使用后重新计算保存期限；无需通过自动生成来保活。接口和保存规则以 [Voice replication](https://ai.google.dev/gemini-api/docs/voice-replication) 与 [Speech generation](https://ai.google.dev/gemini-api/docs/speech-generation) 为准。

## 给文章加声音

搜索并选择文章，再选择“听重点”“听这一节”或“问答讲解”。先点击“根据原文整理讲解稿”，核对并编辑文字，再点击“生成讲解试听”。整理使用 Google 官方 `gemini-3.8-flash`；配音默认使用 Charon，已创建个人音色时复用该音色，不会每篇重新创建。

“听重点”帮助读者判断是否细读；“听这一节”只发送所选章节，播放器会链接回正文中的真实标题；“问答讲解”用同一个作者音色回答几个读者问题，不虚构两位真人对谈。全文朗读不作为默认入口。整理稿只依据原文，不补写作者的新经历或立场。模型结果仍需作者核对，不能把自动整理当作事实验证。

也可以直接填写作者导语或后记，或上传本人原声；原声只在本机转换，不调用模型。所有模式都经过试听确认才写入公开文件。整理、配音都按作者主动操作调用；浏览器刷新不会重复提交已保存的任务。最近的讲解稿可以恢复后继续编辑。
长稿按完整文本自动分段生成，显示实际片段进度，可停止；相同模型、声音、表达方式和片段命中缓存时不再次生成。创建、刷新、轮询和重新进入工具不会重试已失败或结果不确定的付费操作。再次主动生成可能再次计费，已经完成的片段仍可复用。重启后未完成的任务标为中断。

试听并核对文字后，勾选确认，再点击“确认并加入文章”。工具会：

1. 输出 `static/audio/author/<asset-id>.mp3` 和对应的公开文字稿清单。
2. 给读者讲解写入 `authorAudioTracks: [<asset-id>, ...]`；同一篇可同时保存重点、问答及不同章节，更新时只替换同一用途的音频；章节按标题与同名序号对应，前方增删文字不会误删另一节的音频。作者导语或后记兼容原有 `authorAudio: <asset-id>`，保留其他字段和正文。
3. 保持未发布状态，由博客原有的代码审阅和发布流程交付。

这一步会公开选定的音频和文字稿，请在确认前检查内容。个人声音 ID、原始参考录音、授权录音、缓存和密钥不会进入公开清单。`.author-voice/` 不应加入 Git。

音频依据标题与正文的摘要绑定文章版本。准备后正文有变化时，工具拒绝直接挂载；已发布音频遇到后续正文更新，播放器会说明它对应较早版本。若重新生成，必须重新试听确认。

读者入口区分“AI 旁白”“作者原声”和“作者音色合成”，支持切换用途、倍速、下载和文字稿。已准备讲解的章节旁显示“听这一节”，点击就开始播放，再点可暂停。播放进度和倍速只保存在读者自己的浏览器，重新播放时可接着听，不统计或上传收听记录。默认不自动播放、不预加载音频；读者点击入口后才尝试播放，浏览器阻止时可使用原生播放按钮。静态备份站也能播放，不依赖 Gemini。

## 数据与验证

本机任务、个人声音、缓存及未确认稿均在 `.author-voice/`，只有显式确认才写公开文件。作者工具有启动令牌、仅本机绑定、Host/Origin 检查、HttpOnly 会话、请求体上限和单实例锁；它不应部署为公开服务。若端口占用，可使用 `--port 8637`。

```sh
npm run voice:test
```

测试使用隔离目录与模拟供应商，覆盖完整稿件、复用、付费幂等、取消、密钥边界、录音格式、试听确认、文章版本和实际 Hugo 渲染。测试通过不能证明个人音色相似度；首次个人声音仍须作者提供真实录音并试听。第三方 API 的真实可用性与模拟音频播放验收分别记录。

## 当前接入状态（2026-10-17）

博客已在本机通过文件路径读取 Leafhour 同一份 Gemini 密钥；真实整理接口已验证。用户提供了参考录音和包含中文授权语句的本人录音。Google 的普通转录能识别完整授权句，但专用音色核验返回 HTTP 500，内部原因是授权语句不匹配；当前没有返回真实个人声音 ID，复刻尚未成功。录音、转录与真实测试任务均保留在被 Git 忽略的私有目录，不进入公开代码。

遇到这一错误时，工具会提示授权核验失败，不自动重复提交；失败的音色创建任务不会自动变成旁白生成任务。文章仍可单独使用默认的 Charon 通用旁白。若以后需要创建个人音色，可在同一安静环境重新录制参考与授权片段，或尝试官方支持的英文授权句：I am the owner of this voice and I consent to Google using this voice to create a synthetic voice model.

生产网页只播放预先确认的静态音频，不需要配置线上 Gemini 密钥。没有已确认音频的文章保持原来的阅读界面，不显示空播放器。
