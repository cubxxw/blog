## 决策记录

| 决策 | 理由 | 限制或代价 |
| --- | --- | --- |
| 在现有 main 工作区执行，明确文件所有权 | 仓库约定直接 main；保留无关 output | 本地共享工作区，靠命名暂存与集成验证隔离 |
| 当前会话集成，子代理做模块和独立审查，PI 做只读预检 | 作者选择 B 并明确要求子代理 | 共享接口需要整体验证 |
| 报告显式区分 enforce/report-only；发布独立推导所需检查 | 防止报告模式或产物自述绕过门禁 | 旧报告缺字段时明确拒绝 |
| 函数显式 ZIP 复用，隔离临时构建/部署目录 | CLI 函数缓存仅短期有效且含本机路径 | 需要实际 draft 验证云端兼容性 |
| 未知比较基线不等同于所有文章新写 | 保留原有 changed-only 文风政策 | 全历史文风问题留在维护报告 |
| 备用站省略 Critical CSS 和函数 | 绝对 Pages 样式 URL 会导致插件读取远端旧文件；无函数后端 | 备用首屏未做该性能优化 |
| Pages 已改手动，原部署保持服务 | 用户选择 A；移除冗余自动发布 | 内容新鲜度依赖手动更新；早于新工具链的版本不支持该入口 |
| 本地定向浏览器，完整套件在 CI | 避免资源竞争造成虚假超时 | 不能在 CI 通过前宣称完整浏览器门禁通过 |
| 搜索进度使用独立 Git JSON 账本 | 不新增服务，避免新版本丢失失败 URL | 增加状态提交；这些提交不触发网站发布 |
| 修复标签命令的权限与安全传参 | 已复现注入，不能让旧入口危及新凭据 | 标注限制为维护者的一行命令 |

审查明确保留的边界：影子期旧发布链继续工作；过期证据失败关闭，需恢复可信证据；邮件提供商结果不明需要人工核对；被中断的测试不计为通过。没有用这些边界豁免生产门禁。
